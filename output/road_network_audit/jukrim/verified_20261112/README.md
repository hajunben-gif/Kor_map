# 죽림리마을회관 검증 결과 보존본

이 문서는 2026-11-12 조사에서 생성한 CSV·JSON과 재현 결과를 바탕으로 별도로 작성한 UTF-8 정리본이다. 원본 증거를 교정하거나 덮어쓰지 않았다. `cause/report.md`는 백업 원문 자체의 한국어가 일부 `?`로 손실돼 있으며 그대로 보존했다. 질문표를 임의로 한국어로 복원하지 않았다.

## 확인된 결과

시설 좌표는 위도 36.3667897253441, 경도 126.836798762428이다. 반경 2km와 교차하는 원본 OSM highway way는 90개이며, 필요한 원본 노드 2,566개를 보존해 추출했다. PBF의 기준 시각은 2026-11-09 21:22:17 UTC이다. 다음은 시설 좌표에서 원본 도로 형상까지의 거리이며 주행거리가 아니다.

| 조건 | 거리(m) |
|---|---:|
| 기존 청양군 drive | 1359.55122 |
| 기존 부여군 비교 도로 | 259.8930035442013 |
| PBF drive | 9.514797320787055 |
| PBF drive_service | 9.514797320787055 |
| PBF 전체 highway | 9.514797320787055 |

최근접 진입도로는 `978430790`, `highway=residential`이다. 교량은 `978430789`, `highway=residential`, `bridge=yes`이다. 둘 다 현재 drive 필터를 통과하지만 기존 두 군 GraphML의 스칼라·리스트 osmid에 없다. 기존 지천로 `166680097`은 부여군 GraphML에 있다.

## 검증된 국소 누락 메커니즘

1. 진입도로의 원본 노드 22개는 모두 청양군 내부다. 교량은 청양군 노드 `9053552621`과 부여군 노드 `1781315489`를 연결한다. 후자는 지천로와 공유하는 실제 OSM 노드다.
2. 기존 설정은 OSMnx 2.1.1의 `network_type='drive', simplify=True, retain_all=True, truncate_by_edge=False`다. 실제 함수는 500m 버퍼 → 버퍼 절단 → 단순화 → 원래 행정경계 절단 순서로 처리한다.
3. 단순화는 진입도로와 교량을 `1781315489 ↔ 11270863949` 간선으로 합친다. 두 way ID는 osmid 리스트에 남고 중간 노드 좌표도 형상에 남는다. 단순화 자체가 ID를 버린 것은 아니다.
4. 최종 절단은 경계 밖 그래프 노드와 그에 연결된 간선 전체를 제거한다. 간선의 한 끝점이 다른 군에 있어 각 군에서 합쳐진 간선 전체가 사라진다. 내부를 지나는 형상을 경계에서 잘라 보존하는 처리와 다르다.
5. 기존 청양군 GraphML에는 끝점 `11270863949`만 같은 좌표의 차수 0 노드로 남는다. 부여군에는 지천로 접속 노드 `1781315489`가 남는다. 이 흔적이 국소 재현과 일치한다.

| 재현 설정 | 진입도로 | 교량 |
|---|---|---|
| 청양군, simplify=False, truncate_by_edge=False | 유지 | 제거 |
| 각 군, simplify=True, truncate_by_edge=False | 제거 | 제거 |
| 각 군, simplify=True, truncate_by_edge=True | 유지 | 유지 |
| 두 군 합집합, simplify=True, truncate_by_edge=False | 유지 | 유지 |

`retain_all=True`이므로 최대 연결요소 선택이 원인은 아니다. 대상은 고립 순환고리도 아니다. residential 도로가 drive 필터에서 제외됐다는 설명이나 다른 간선 ID에 단순히 숨겨졌다는 설명은 증거와 맞지 않는다.

## 과거 캐시와 결론의 범위

기존 `downloads/korea-road-network.zip`에서 과거 캐시 두 개를 찾았다. ZIP은 이번 보존본에 새로 추가하지 않는다. 관련 캐시의 OSM 기준 시각은 청양군 관련 2026-11-09 04:57:43 UTC, 부여군 관련 04:54:30 UTC이다. 그래프 생성 시각은 각각 04:59:04 UTC, 04:55:41 UTC이다.

두 캐시에서 세 도로의 전체 노드 목록·태그·참조 노드 좌표가 이번 PBF 결과와 정확히 일치했다. 진입도로 way 변경 시각은 2023-10-18, 교량은 2021-09-01, 지천로는 2024-01-08이다. way 변경 시각만으로 개별 노드의 변경 이력을 단정하지 않았고 좌표도 직접 대조했다.

원래 PBF 지역 자료 조합 12개와 과거 캐시의 작은 지역 부분집합 조합 6개를 검증했다. 보존된 과거 입력은 청양군 관련 16 way/588 node, 부여군 관련 33 way/810 node이다. 대상 가지에 연결되는 추가 way 누락이 없는지도 조사했다. 전체 군 네트워크나 전국 네트워크를 재구축한 결과가 아니다.

원래 요청·당시 런타임 전체 설정을 완전히 복원하지 않았으며, 현재 경계로 다시 만든 요청 캐시 키는 ZIP 파일명과 일치하지 않았다. 따라서 과거 HTTP 요청과 캐시의 일대일 대응이나 당시 전체 실행의 완전 재현은 확정하지 않는다. ZIP 안 코드·두 GraphML·경계는 현재 파일과 줄바꿈만 정규화하면 일치했다. 원래 바이트 해시가 같다는 뜻은 아니다. 확인한 국소 삭제 메커니즘을 다른 시설·다른 지역 전체의 원인으로 일반화하지 않는다.

## 다음 작업에서 지킬 사항

- 경계 횡단 간선과 외부 연결 노드를 보존해야 한다. `truncate_by_edge=True`는 이번 회귀를 통과했지만 모든 관통 간선을 보장하는 만능 해결책은 아니다.
- 필요하면 두 군 합집합 또는 시설과 연결 도로를 포함하는 완충 범위에서 처리한다. 이미 잘라서 삭제된 군별 그래프를 나중에 합치는 것만으로는 복원되지 않는다.
- `retain_all=True`를 유지하고, 단순화를 무조건 끄기보다 경계·교량·osmid 보존 회귀를 검사한다. 이번 업로드는 `extract.py`나 생산 도로망 설정을 변경하지 않는다.
- 실제 차량 통행권·노면·폭·장애물·교량 하중·구호차량 적합성은 미확인이다. OSM 연결이나 필터 통과를 통행 승인으로 간주하지 않는다.
- 전체 도로망 재구축·다른 시설·침수위험·최적화 작업은 별도 사용자 지시 전까지 진행하지 않는다.

## 파일 안내와 무결성

- `pbf_results/`: 기존 결과 5개를 바이트 그대로 복사했다.
- `cause/`: 원인 보고서 원문, 노드·way 비교, 과거 입력과 재현 결과, 시각·보존 검증을 복사했다.
- `*_summary.json`: 중복 형상 또는 긴 요청 문자열을 제외한 파생 요약이다. 원본 해시와 파생 파일 해시는 `manifest.json`에 구분해 기록했다.
- `manifest.json`: 복사 원본·SHA-256·바이트 크기·요약 여부를 기록한다. JSON 안의 Windows 임시 경로는 과거 실행의 출처 기록이며 Cloud의 입력 경로가 아니다.
- 이 보존 디렉터리는 `.gitattributes`로 줄바꿈 자동 변환을 막았다. Windows 원본의 바이트와 SHA-256을 Linux Cloud 체크아웃에서도 유지하기 위한 설정이다.
- 중복된 전체 pipeline/trial 형상 덤프, 전체 캐시, ZIP, PBF, SQLite, 임시 실행 폴더 및 경로가 고정된 일회성 스크립트는 추가하지 않았다.

Cloud 재현과 작업 범위는 [인계 문서](../../../../docs/JUKRIM_CLOUD_HANDOFF.md)를 참고한다.
